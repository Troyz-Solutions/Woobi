3. How the Architecture Works: Interactions & Lifecycle

1. Core State & Routing

Store.js provides a reactive single source of truth. All user actions (changing outfits, selecting occasions, recording daily streaks) update state and trigger subscribers. State automatically writes to localStorage with legacy key migration adapters.

2. 3D Studio Engine

The Three.js engine binds lighting, camera framing, stage geometry, and rigged avatar meshes. When garments are equipped, geometry is dynamically bound to the avatar skeleton and shaders automatically adapt to the active studio lighting preset.

3. High-Level Studio Features

Virtual Try-On disposes of replaced garment meshes cleanly from GPU memory to prevent WebGL memory leaks. Garment interactions run raycasting on pointer move for hover states without stalling camera orbit controls.

4. Browser-Safe Backend Client SDK

Frontend code never accesses server internals directly. Communication occurs exclusively through createApiClient() over HTTP REST. Responses use standard JSON envelopes ({ success, data, error }).

4. How It Prevents Issues: Safety, Durability & Hardening

Hazard / Risk Prevention Mechanism Engineering Verification
Circular Dependencies & Module Leaks AST Boundary Enforcer (validate-boundaries.ps1) enforces public-only index.js imports and blocks browser imports of backend files. Automated CI step checks all 5 primary domains. 0 Violations
Multi-Process Concurrent Write Collisions Kernel-level OS directory locking (.oslock via fs.mkdirSync) + temporary staging files with atomic fs.renameSync. test-multiprocess-concurrency.js executes 4 simultaneous worker processes with 0 lost writes.
Sudden Server Crash / Corrupted JSON Dual snapshot rotation writes .bak copies before any file modification. If JSON parsing fails, readCollection auto-restores from backup. Simulated crash test corrupts primary JSON; auto-healing recovers data and emits RECOVERED_FROM_BACKUP.
Stale Multi-Process Cache Drift readCollection() verifies physical file mtimeMs against in-memory cache timestamps. Disk changes immediately invalidate cache. Cross-process revocation test confirms changes by Worker 1 are immediately observed by Worker 2.
Unauthorized Entitlement Tampering NODE_ENV === 'production' strictly blocks developer verification bypass keys (DEVELOPMENT_BYPASS_KEY) for premium features. HTTP scenario 14 confirms dev bypass keys return HTTP 403 Forbidden in production mode.
Mobile WebGL Context Dropping Three.js lifecycle handlers listen for webglcontextlost to stop render loops, and webglcontextrestored to rebuild scene geometry. User Journey 7 verifies context restoration without state loss or application crashes.

5.3 Production Deployment (PM2 Single-Writer Mode)

Because Woobi uses an atomic local-first JSON database, the application is strictly configured for single-process execution (instances: 1, exec_mode: 'fork') in PM2. Multi-worker cluster mode is prohibited to eliminate concurrent worker file contention. 

# Start application under PM2 in production single-writer mode
pm2 start ecosystem.config.cjs --env production

# Persist PM2 across host server reboots
pm2 save
pm2 startup

# Inspect live cluster logs and health
pm2 logs woobi-backend
pm2 status
